## Wave Sequence

### Wave 0 — Mobile-first foundation ⭐ highest priority

**Ships before Wave 1.** iPhone browser/Safari is our eventual core user base — the game should feel built for a phone in your hand first, with desktop as the thing that still happens to work, not the other way around.

> **Current state, checked against the code:** `.game-layout` only collapses its two-column grid at 900px — the `TopBar` above it stays one long flex row of 7 stats plus a headline plus a Menu button, which wraps/overflows badly under ~430px. `.board` is a fixed 4×4 grid with 96px-min tiles sized for a desktop pointer, not a thumb on a 375px-wide screen. `index.html`'s viewport meta has no `viewport-fit=cover`, so `env(safe-area-inset-*)` never activates — nothing accounts for the notch/Dynamic Island or home indicator. There's no `apple-touch-icon`/`theme-color`/`apple-mobile-web-app-capable`, so "Add to Home Screen" looks like a bare bookmark. Buttons across `LocationPanel.tsx` use the default `0.45rem 0.9rem` padding with no min-height — several fall under Apple's 44×44pt touch-target minimum. (Fixed below — this note originally also claimed `:active` was missing; it wasn't, that part was wrong.)
>
> **Non-UI risk worth flagging here too:** `GameContext.tsx` already autosaves to `localStorage` after every action (good), but iOS Safari's Intelligent Tracking Prevention purges localStorage for sites the player hasn't opened in ~7 days — and IndexedDB isn't exempt either. An installed ("Add to Home Screen") PWA _is_ exempt. So Home Screen presence below isn't just a nice icon — for a game people come back to over days/weeks, it's what keeps their save alive at all.
>
> **UI test-coverage note, mirroring Wave 2's below:** `src/ui/__tests__/` has one file (`App.test.tsx`) covering `Board.tsx`, `GameScreen.tsx`, and `LocationPanel.tsx` combined — the exact three components this wave rewrites. Add component tests (React Testing Library, already in the stack) for whatever you touch, so the mobile-first rewrite doesn't ship untested.

### Wave 2 — Gameplay depth

Engine + UI pairs. Keep each mechanic in its own module in `src/engine/` with tests; the deterministic-engine pattern (all randomness via `rng.ts`) must hold.

> **Test-coverage note:** the engine currently has one test file (`engine.test.ts`) covering ~1,100 lines across `actions.ts`/`week.ts`/`ai.ts`. Every item below touches this code — backfill unit tests for the module you're editing as you go, not just the new mechanic, so coverage doesn't stay this thin as gameplay depth grows.
>
> `week.ts`'s `personalEvent()` currently rolls 4 flat outcomes (found cash, doctor bill, work bonus, old friend). Health & doctor, Durable goods (robbery), and Loans & credit (garnishment) each add their own outcome to that table — extend it in place rather than starting a parallel event system.
>
> **Ship the first three rows below before any other item in this wave.** Every remaining row changes `PlayerState`'s shape. Right now there's no save-schema versioning (`GameContext.tsx`'s `SAVE_KEY = 'fastlane-save-v1'` is a hardcoded string nobody's required to bump) and no error boundary anywhere in the app — so a shape change today would silently corrupt an old save with `undefined` fields (which then autosaves right back over the real save) or white-screen the app with no recovery path. Land the safety net first.

## How To Pull Work

1. Check **In Progress / Up Next**. Finish 🟡 items before pulling new work.
2. Otherwise pull the topmost ⬜ from the active wave.
3. Mark it 🟡 in the same commit as the first code change.
4. When shipped: mark ✅ YYYY-MM-DD, promote the next ⬜, update CHANGELOG.md — same commit.
5. Every item lands with tests passing (`pnpm lint && pnpm type-check && pnpm test`) and deploys via push to `main`.
