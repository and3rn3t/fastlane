## Wave Sequence

> **Two different meanings of "Wave," by design.** Waves 0–6 shipped as a strict sequence — each one assumed everything before it was done, and "pull the topmost ⬜ item" meant something unambiguous. Waves 7–13 are **independent thematic tracks**, not a continuation of that sequence: pull from whichever wave you want, in any order, _except_ where a wave's own preamble or a row explicitly says otherwise (dependencies are always called out inline — search this doc for "Depends on" / "Builds on" / "Pull ... before" rather than assuming wave number implies order). Wave 13 in particular is a cross-cutting prerequisite for balance-sensitive work in Waves 7, 9, and 12, despite sitting last numerically — see its own preamble.

### Wave 0 — Mobile-first foundation ✅ complete (2026-08-24)

iPhone browser/Safari is our eventual core user base — the game should feel built for a phone in your hand first, with desktop as the thing that still happens to work, not the other way around. Every item below shipped; real-device QA (see the last row) caught 2 bugs neither Chromium testing nor code review would have.

> **Current state, checked against the code:** `.game-layout` only collapses its two-column grid at 900px — the `TopBar` above it stays one long flex row of 7 stats plus a headline plus a Menu button, which wraps/overflows badly under ~430px. `.board` is a fixed 4×4 grid with 96px-min tiles sized for a desktop pointer, not a thumb on a 375px-wide screen. `index.html`'s viewport meta has no `viewport-fit=cover`, so `env(safe-area-inset-*)` never activates — nothing accounts for the notch/Dynamic Island or home indicator. There's no `apple-touch-icon`/`theme-color`/`apple-mobile-web-app-capable`, so "Add to Home Screen" looks like a bare bookmark. Buttons across `LocationPanel.tsx` use the default `0.45rem 0.9rem` padding with no min-height — several fall under Apple's 44×44pt touch-target minimum. (Fixed below — this note originally also claimed `:active` was missing; it wasn't, that part was wrong.)
>
> **Non-UI risk worth flagging here too:** `GameContext.tsx` already autosaves to `localStorage` after every action (good), but iOS Safari's Intelligent Tracking Prevention purges localStorage for sites the player hasn't opened in ~7 days — and IndexedDB isn't exempt either. An installed ("Add to Home Screen") PWA _is_ exempt. So Home Screen presence below isn't just a nice icon — for a game people come back to over days/weeks, it's what keeps their save alive at all.
>
> **UI test-coverage note, mirroring Wave 2's below:** `src/ui/__tests__/` has one file (`App.test.tsx`) covering `Board.tsx`, `GameScreen.tsx`, and `LocationPanel.tsx` combined — the exact three components this wave rewrites. Add component tests (React Testing Library, already in the stack) for whatever you touch, so the mobile-first rewrite doesn't ship untested.
