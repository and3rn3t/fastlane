## Standing Constraints

These bind every wave below, and every wave anyone adds later. They live here once instead of being restated in each wave's preamble — if a constraint changes, change it here.

**No multiplayer.** Per explicit, standing user direction. Every rival is an AI opponent driven through `runAIWeek()`, same as Riley today. Reviving it is not a UI-flow change: `GameState` has fixed `player`/`riley` fields and `PlayerKey` is a two-value union — not an array — used throughout `ai.ts`/`actions.ts`/`week.ts`. Hot-seat (Wave 3) and async multiplayer (Wave 4) were both cut for this reason.

**No new gambling mechanics.** Lottery and Casino are the ceiling for the whole roadmap. A "Fortune Teller" paid-random-card location (Wave 7) and an "Arcade corner: Blackjack & Slots" (Wave 10) were each considered and cut against this rule. High-variance _investing_ — Wave 9's Crypto corner — is not gambling and does not count: no house edge, no instant win/loss roll.

**Board locations: the frame is full.** `LocationId` is a closed union of 14, filling every cell of the 4×5 grid. `Board.tsx`'s `PERIMETER` is now derived (`perimeterForSize(LOOP_SIZE)`, shipped 2026-09-11 — Wave 15's Data-driven board geometry) rather than hand-listed, so growing `LOOP_SIZE` no longer needs a manual grid-position edit — but the grid itself is still physically full: the current 5×4 rectangle has no spare border cell left. The next location needs a bigger grid shape, not an appended row — and any addition still shifts wrap-around travel costs for every existing pair, since `travelCost()` is `min(diff, LOOP_SIZE - diff)`. Until a future row picks that bigger shape, fold new features into an existing location's panel (the way Home Insurance folded into First Bank).

**Save migrations are not optional.** Any `PlayerState`/`GameState` shape change bumps `SAVE_VERSION` (`engine/types.ts`, currently 11) _and_ adds a step to the `MIGRATIONS` map in `state/GameContext.tsx`. Rows below flag "save migration required" where it applies, but the rule holds whether or not a row says so.

**Riley plays by the same rules.** The AI must only ever act through the same action functions as the human (`actions.ts`), never by mutating state directly. A mechanic the player can use and Riley structurally cannot is a balance decision, not a shortcut — see the sim rule below.

**Balance lives in `data.ts`.** Tunable numbers — prices, weights, thresholds, outcome tables — go in `data.ts` as named constants, not inline in `week.ts`/`actions.ts`. This has been caught in review more than once.

**Sim before you call an economy-touching row done.** Run `pnpm sim` (single cell) and `pnpm sim:report` (the full `AI_PROFILES × RULE_PRESETS` matrix, which fails CI on a flagged cell), and record the before/after split in the row's notes. Treat **>10 points** of win-rate drift as the threshold that needs explaining or rebalancing.

> **Known fragility, learned the hard way in Wave 7 — read this before changing anything in `week.ts`'s weekly sequence.** Several engine tests depend on brute-forced seeds. Changing the _number_ of RNG draws per week — not just their outcomes — shifts the shared `rngSeed` stream from that week onward in every game, desyncing those tests and moving sim win rates by several points on its own. Seasons and Holiday one-offs each did this (a cumulative ~10.5-point shift) by skipping the `HEADLINES` roll on some weeks; Wilder global headlines deliberately kept the draw _count_ identical and needed zero seed re-finding as a result. If a change moves the win rate, check whether it changed draw count before assuming it changed balance. Re-find broken seeds by brute force and re-comment them — never silently hardcode around the new value.

## Wave Sequence

> **"Wave" means two different things in this doc, by design.** Waves 0–6 shipped as a strict sequence — each assumed everything before it was done, and "pull the topmost ⬜" was unambiguous. **Waves 7 and up are independent thematic tracks**, not a continuation of that sequence: pull from whichever wave you like, in any order, except where a row says otherwise. Dependencies are always called out inline — search for "Depends on" / "Builds on" / "Pull … before" rather than inferring anything from wave numbers. Two cross-cutting ones worth knowing up front: **Wave 13** (simulation tooling, already complete) is what makes the balance guidance in Waves 9/14/15 actionable, and **Wave 15's Data-driven board geometry** (shipped 2026-09-11) means growing `LOOP_SIZE` is now a `data.ts` change instead of a manual grid edit — though the grid itself is still physically full until a bigger shape is picked, see Standing Constraints.

## How To Pull Work

1. Read **Standing Constraints** once. They are not per-wave advice — they bind whatever you pull.
2. Check **In Progress / Up Next**. Finish 🟡 items before pulling new work.
3. Otherwise: Waves 0–6 are a finished strict sequence. **For Waves 7+, pull any ⬜ from any wave** — they are independent tracks, not ordered by number — except where a "Depends on" / "Builds on" / "Pull … before" note says otherwise.
4. Mark it 🟡 in the same commit as the first code change.
5. When shipped: mark ✅ YYYY-MM-DD, write the one-line summary in the row, put the full engineering notes in [ROADMAP-ARCHIVE.md](ROADMAP-ARCHIVE.md) under that wave, promote the next ⬜, update CHANGELOG.md — same commit.
6. Every item lands with `pnpm lint && pnpm type-check && pnpm test` passing, plus `pnpm sim` / `pnpm sim:report` for anything economy-touching.

> **Keep this file scannable.** It reached 240KB once, because shipped rows accumulated full engineering postmortems inside their Notes cells until the "what's next" doc was mostly archaeology. The archive split exists to stop that recurring, and there is exactly one rule that keeps it working: **a row's Notes cell is one sentence — the full detail goes in [ROADMAP-ARCHIVE.md](ROADMAP-ARCHIVE.md) under that wave.** (Prettier pads these table columns to align on every `pnpm format`, which is fine and enforced by CI — but it means a long cell inflates the whole column, so length here costs more than it looks.)
